Construction DWH

Data Warehouse per il controllo di gestione di commessa, con un flusso ETL in Python che carica dati Pianificati, Impegnati e Consuntivi da file Excel verso PostgreSQL.

Cosa contiene il progetto

Schema SQL

construction_dwh.sql e construction_dwh_v2.sql (modello Kimball con membri sconosciuti -1).

Generatore template

create_excel_templates.py crea Planned.xlsx, Committed.xlsx e Actual.xlsx.

Loader ETL

load_excel_to_dwh.py risolve le chiavi di business e inserisce nelle tabelle dei fatti.

Dipendenze

requirements.txt – installazione con pip install -r requirements.txt.

Architettura del flusso

Le tre tabelle dei fatti

Planned

dwh.FactPlanned

Valori di budget / pianificazione per WBS, risorsa e periodo.

Committed

dwh.FactCommitted

Ordinato e impegni verso fornitori.

Actual

dwh.FactActual

Consuntivo: costi e ricavi effettivamente sostenuti.

Processo end-to-end

  1. Crea lo schema del Data Warehouse

    Esegui uno degli script SQL nel database (schema consigliato: dwh). Il loader supporta la nomenclatura Kimball (DimDate, DimWBS, ProjectBK…).

  2. Installa le dipendenze Python

    pip install -r requirements.txt

  3. Genera i template Excel

    python create_excel_templates.py

    Produce Planned.xlsx, Committed.xlsx, Actual.xlsx.

  4. Compila i file Excel

    Ogni file deve mantenere queste colonne (la prima riga è un esempio sovrascrivibile):

    ProjectBKWBSBKDateKeyResourceBKCustomerBKSupplierBKProductBK DocumentNumberDocumentLineNumberQuantityHoursCostRevenueSourceSystem

  5. Configura la connessione al database

    $env:DWH_CONN_STR = "postgresql://postgres:postgres@localhost:5432/ConstructionDWH"

    In alternativa usa l'opzione --connection-string.

  6. Valida con un dry run (consigliato)

    python load_excel_to_dwh.py --excel-dir . --schema dwh --dry-run

    Controlla file e risoluzione delle chiavi senza inserire righe.

  7. Carica i dati nelle tabelle dei fatti

    python load_excel_to_dwh.py --excel-dir . --schema dwh

Risoluzione delle chiavi

Per ogni riga il loader trasforma le business key in chiavi surrogate:

Colonna ExcelLookup nel DWH
ProjectBKDimProject.ProjectBK
WBSBKDimWBS.WBSBK
ResourceBKDimResource.ResourceBK
CustomerBKDimCustomer.CustomerBK
SupplierBKDimSupplier.SupplierBK
ProductBKDimProduct.ProductBK
DateKeyDimDate.DateKey

Se un lookup non trova corrispondenza, il loader usa -1 (unknown member).

Note

  • Assicurati che i membri sconosciuti (-1) esistano nelle dimensioni (già inclusi in construction_dwh_v2.sql).
  • Se sono presenti DimAudit/AuditKey, il loader scrive automaticamente lo stato di audit.
  • Lo schema di destinazione è configurabile con --schema.
